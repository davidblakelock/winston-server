Winston has several critical bugs that need to be fixed systematically. Please address all of them in one comprehensive update.
Bug 1 — App goes stale overnight: Winston stops responding after being open for several hours. The user has to restart the app. Please implement an automatic keep-alive and reconnection system. Every 5 minutes the frontend should ping the server at a /api/health endpoint to keep the connection alive. If the server does not respond the frontend should automatically attempt to reconnect every 30 seconds. If the API call fails with any error the frontend should show a subtle reconnecting message and retry automatically rather than showing I am having trouble right now. Add automatic session refresh so Google OAuth tokens are renewed before they expire — typically every hour.
Bug 2 — Notifications firing on wrong device: When David sets a reminder on his phone it should fire on his phone. When set on his laptop it should fire on his laptop. AND ideally on all devices. The current system is firing notifications on the wrong device. Please fix the push subscription system so that every device that has granted notification permission has its own row in the push_subscriptions table in Supabase with a device identifier. When a reminder fires send push notifications to ALL registered devices for that user — not just one. This way regardless of which device set the reminder all of David's devices get notified.
Bug 3 — Push subscriptions still not saving: The push_subscriptions table is empty. This is the root cause of notification problems. Please completely rebuild the push notification subscription flow. On every page load check if the browser supports push notifications. If the user has previously granted permission automatically re-register the push subscription and save it to Supabase. Do not wait for the user to click a button — do this automatically and silently on every app load. This ensures the subscription is always current in Supabase even after a migration or server restart. Add a visible notification status indicator somewhere in the UI — a small bell icon that shows green if notifications are enabled and red if not. Clicking it allows the user to re-enable notifications.
Bug 4 — Navigation not opening Google Maps: When David says take me to my doctor or similar Emma Peel confirms verbally but does not actually open Google Maps. Fix this by adding a structured action response system. When the backend detects a navigation request include an action object in the API response alongside the text response. The action object should contain type navigate and url with the complete Google Maps URL. The frontend must check every API response for an action object and execute it immediately. For navigation execute window.open with the Google Maps URL. This must actually open the browser to the URL — not just have Emma Peel say she will.
Bug 5 — Error message I am having trouble right now: This appears when the API call fails. Please improve error handling throughout Winston. Instead of showing a generic error message Emma Peel should say something warm like I seem to be having a moment — give me just a second and then automatically retry the request once. If the retry also fails say I am having some technical difficulties right now. Everything should be back to normal shortly. Then automatically retry every 30 seconds until the connection is restored. Never leave the user with a dead interface.
Bug 6 — Session expiry: Google OAuth tokens expire after one hour. When the token expires all API calls fail which causes the stale app problem and the error messages. Please implement automatic token refresh. Before every API call check if the OAuth token is still valid. If it expires within 5 minutes proactively refresh it. If it has already expired silently redirect to Google Sign In and return the user to exactly where they were after re-authentication.
After fixing all six bugs please add a system health check that runs every 5 minutes and logs the status of: database connection, push notification service, OAuth token validity, and API connectivity. This gives us visibility into any problems before users experience them
