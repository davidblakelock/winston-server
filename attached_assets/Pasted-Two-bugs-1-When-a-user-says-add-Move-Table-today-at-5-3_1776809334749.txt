All tests pass. Here's what was wrong and what was fixed:

Bug 1 — "Add Move Table" routed to modify instead of create

Root cause: the code evaluated the modify pattern first. The regex for modify is move\s+(my\s+)?(?!\w+\s+list) — which matched "Move Table" in the event title, so isCalendarModify came back true and isCalendarCreate was forced to false. It then searched your calendar for an existing "Move Table" event, found nothing, and gave up.

Fix: flip the evaluation order — isCalendarCreate is checked first. An explicit "add" keyword always wins. isCalendarModify only fires when there's no create keyword. Verified with the test message: now correctly routes to CREATE.

Bug 2 — "I don't have access to previous conversations"

Two-part root cause:

The /api/messages endpoint only accepted Bearer session tokens — the native API key was silently rejected with a 401, so the native app couldn't load chat history at all.
Even if the native app sent history: [], the server just used that empty array and Claude had nothing to work with.
Two-part fix:

/api/messages (GET + POST) now accepts the native API key alongside Bearer tokens.
When the server receives an empty history array (not an auto-greeting), it automatically loads the last 20 messages from the database as a fallback — so Winston always has recent conversation context, regardless of whether the client passes history.
